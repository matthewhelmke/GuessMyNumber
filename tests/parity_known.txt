# Known parity divergences: language/scenario pairs that do not match the
# Python reference yet. tests/parity reports these as KNOWN instead of failing.
#
# This list only shrinks. When a fix makes a pair match, tests/parity reports
# it STALE and fails until its line is deleted. Never add a line to silence a
# new divergence; fix the implementation instead.
#
# Format: <language> <scenario>  # cause
# See the diffs with: ./tests/parity <language>
#
# Recorded 2026-10-12, when tests/parity grew from one scenario to eighteen.

bash    unicode-arabic-digit   # [0-9] follows locale collation, so ٣ passes the check and crashes arithmetic
bash    unicode-superscript    # same as above, for ²

c       empty-line             # an empty line is skipped instead of reported non-numeric
c       two-numbers            # "30 40" is not rejected as non-numeric

cobol   careless-low           # LOWMAX is PIC 99, so 100 truncates to 00 and the computer can never find 100
cobol   empty-line             # an empty line is not reported non-numeric
cobol   trim-tabs              # tabs are not trimmed

forth   trim-spaces            # leading and trailing spaces are not trimmed
forth   trim-tabs              # tabs are not trimmed

fortran huge-number            # a long run of digits is not reported out of range
fortran sign-minus             # a sign is accepted as part of the number
fortran sign-plus              # a sign is accepted as part of the number
fortran two-numbers            # "30 40" is not rejected as non-numeric

go      empty-line             # an empty line is not reported non-numeric
go      huge-number            # a long run of digits is not reported out of range

go      sign-minus             # a sign is accepted as part of the number
go      sign-plus              # a sign is accepted as part of the number
go      two-numbers            # "30 40" is not rejected as non-numeric
